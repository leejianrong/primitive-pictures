# Installed on the pod at job-run time (inside the dead-man's-switch-protected
# JOB_CMD, not before it -- see ADR-0001). Not part of the local `pipeline`
# project's own dependencies; this is a different Python environment entirely.
#
# torch itself is expected to already be present in the base pod image
# (config.DEFAULT_POD_IMAGE is a runpod/pytorch image) -- only the
# diffusion-specific stack installs here.
#
# diffusers pinned with an upper bound (2026-09-27, from a real failed run):
# newer diffusers releases eagerly register a flash-attention custom op via
# torch.library.custom_op at IMPORT time (its new "attention backend"
# feature -- see docs/source/en/optimization/attention_backends.md upstream),
# and that registration 500s with "infer_schema(func): Parameter q has
# unsupported type torch.Tensor" against this pod image's torch build --
# even though we never install flash-attn or ask for it. 0.31.0 predates
# that refactor. Verified against a real pod before trusting this pin;
# re-verify the same way before raising it.
# transformers/accelerate pinned exact, not ranged: a range here forced pip's
# resolver into several minutes of silent backtracking against whatever the
# base image pre-installed (observed 2026-09-27). Exact versions make pip's
# install fast and deterministic instead of a solver search.
